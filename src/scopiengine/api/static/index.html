    Syntax
    
            
    
              
                
    field:valueTerm match — analyzed for text fields, exact for keyword.
    
                
    field:"a phrase"Phrase match, position-aware.
    
                
    field:val*Prefix (first analyzed token on text fields).
    
                
    field:(a OR b)Any of several values on one field.
    
                
    field:[a TO b]Inclusive range — numbers, dates, or lexical.
    
                
    field:>=v / >v / <=v / <vOne-sided range.
    
                
    _exists_:fieldDocument has any value for field.
    
                
    AND / OR / NOT / !Uppercase only. Adjacent terms with no operator are an implicit AND.
    
                
    @timestamp:>now-1hRelative time — units s/m/h/d/w.
    
                  
            
    

            
    Pipe stages
    
            
    
              
                
    | sort -fieldReal index-wide sort, not page-local. - for descending. Comma-separate for multi-key.
    
                
    | limit NCap the number of hits returned.
    
                
    | fields a,b,cProject _source down to just these fields.
    
                
    | stats count() by fieldBucket every match by field, counted.
    
                  
            
    

            
    Field resolution
    
            
    
              A dynamically-mapped string field is indexed twice: analyzed as
              field (matches individual words) and verbatim as
              field.keyword (matches the whole value exactly). For an id-like
              value — trace_id, request_id, order_id — search
              field.keyword or you'll match every document that shares a token
              (e.g. a common prefix before a hyphen). An explicitly mapped keyword
              field (see examples/mappings/logs.json) doesn't need the suffix — there's only
              one form of it.
            
    
            
    
              A field name that isn't mapped at all is not a parse error — the query still runs, it
              just matches nothing. A sort that has to inspect more than
              max_sort_candidates matches sets scopi.sort_truncated: true in
              the response rather than silently returning a wrong-looking-complete page; narrow the
              query with a filter first if you see it.
